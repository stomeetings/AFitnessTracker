# Native demo plan: Android APK without Android Studio

*Written 2026-11-17 for the next-day demo on a Samsung Galaxy A52. Nothing in the pose tracking or the backend changes.*

## What the APK is (and is not)

The APK is a **Capacitor WebView shell** whose `server.url` is the tunnel address. When it opens, it loads the same app the
phone's browser loads today, from the backend through the tunnel. On-device MediaPipe, voice, rep counting and fall detection
behave exactly as in Chrome on the phone. The backend switches in `backend/.env` (`ANGLES_3D=0` etc.) still apply.

Consequences to know before the demo:

- **The tunnel URL is built into the APK.** A quick `trycloudflare` tunnel gets a new address on every start, so after a tunnel
  restart the APK must be rebuilt and reinstalled (the script does it in about a minute after the first build). **Start the tunnel
  once and leave it running for the whole demo.** For a fixed address, use a named Cloudflare tunnel or ngrok's free static domain.
- **The URL must be `https://`.** `getUserMedia` only works in a secure context, so `http://<LAN IP>` opens the app but the camera
  is refused. That is also why `cleartext` is only switched on for an `http://` URL. Both tunnels give `https`, which also means
  no mixed-content or network-security-config work is needed.
- **The access token is NOT built into the APK.** Type it once in the app (the same token screen as in the browser).
- **Fallback if anything with the APK fails:** open the same tunnel URL in Chrome on the phone. It is the same app.

Versions: you asked for JDK 17 and `android-34`. Current Capacitor (7 and later) needs **JDK 21** and a newer `compileSdk`, so
install JDK 21. Check which platform the generated project wants (step 2.4) and install that one instead of guessing.

## 1. One-time: Android command-line build environment (no Android Studio)

Run these in **PowerShell** (not through Claude Code's `!`), then **open a new terminal** so the variables apply.

### 1.1 JDK 21

```powershell
winget install --id EclipseAdoptium.Temurin.21.JDK -e
```

### 1.2 Android command-line tools

The version number in the zip name changes over time. If this link is gone, take the "Command line tools only / Windows" link
from https://developer.android.com/studio#command-line-tools-only.

```powershell
$sdk = "$env:LOCALAPPDATA\Android\Sdk"
New-Item -ItemType Directory -Force "$sdk\cmdline-tools" | Out-Null
Invoke-WebRequest https://dl.google.com/android/repository/commandlinetools-win-11076708_latest.zip -OutFile "$env:TEMP\cmdtools.zip"
Expand-Archive "$env:TEMP\cmdtools.zip" "$sdk\cmdline-tools" -Force
Rename-Item "$sdk\cmdline-tools\cmdline-tools" latest      # sdkmanager must live in cmdline-tools\latest\bin
```

### 1.3 Environment variables (user level, permanent)

```powershell
$sdk  = "$env:LOCALAPPDATA\Android\Sdk"
$jdk  = (Get-ChildItem "C:\Program Files\Eclipse Adoptium" -Directory -Filter "jdk-21*" | Select-Object -First 1).FullName
[Environment]::SetEnvironmentVariable("ANDROID_HOME", $sdk, "User")
[Environment]::SetEnvironmentVariable("JAVA_HOME", $jdk, "User")
$p = [Environment]::GetEnvironmentVariable("Path", "User")
[Environment]::SetEnvironmentVariable("Path", "$p;$jdk\bin;$sdk\cmdline-tools\latest\bin;$sdk\platform-tools", "User")
```

Close the terminal, open a new one, and check:

```powershell
java -version          # 21.x
sdkmanager --version
```

### 1.4 SDK packages

```powershell
sdkmanager --licenses                                  # answer y to each
sdkmanager "platform-tools" "platforms;android-35" "build-tools;35.0.0"
```

After step 2.4, compare with `compileSdkVersion` in `frontend/android/variables.gradle`. If it says 36, also run
`sdkmanager "platforms;android-36"`. With the licenses accepted, Gradle downloads a missing build-tools version itself.

### 1.5 If a download fails with a certificate error

The same certificate problem `uv` had earlier (`UnknownIssuer`) shows up in Java as `PKIX path building failed`. Tell Java to
use the Windows certificate store, which already trusts that certificate. Do NOT disable certificate checks. Add these lines to
`%USERPROFILE%\.gradle\gradle.properties` (create the file if needed):

```
systemProp.javax.net.ssl.trustStoreType=Windows-ROOT
org.gradle.jvmargs=-Xmx2g -Djavax.net.ssl.trustStoreType=Windows-ROOT
```

The Gradle wrapper (the step that downloads Gradle itself) does not read that file, only `GRADLE_OPTS`. The script sets
`GRADLE_OPTS=-Djavax.net.ssl.trustStoreType=Windows-ROOT` on Windows. To run `gradlew.bat` by hand, set it yourself first.

## 2. One-time: Capacitor in the frontend

From Git Bash (Claude Code `!` works here):

```bash
cd /c/Projects/AiFitnessTracker/frontend && npm install @capacitor/core @capacitor/android && npm install -D @capacitor/cli
cd /c/Projects/AiFitnessTracker/frontend && npm run build
cd /c/Projects/AiFitnessTracker && backend/.venv/Scripts/python -m pip install qrcode
```

2.1 `npx cap init` is not needed: the script writes the config itself. For reference, this is what it writes
(`frontend/capacitor.config.json`):

```json
{
  "appId": "com.aifitness.tracker",
  "appName": "AI Fitness Tracker",
  "webDir": "dist",
  "server": { "url": "https://<words>.trycloudflare.com", "cleartext": false },
  "android": { "allowMixedContent": false }
}
```

2.2 The first script run (section 4) also runs `npx cap add android`, which creates `frontend/android/`.

2.3 The script adds these lines to `frontend/android/app/src/main/AndroidManifest.xml` (only the missing ones, safe to re-run):

```xml
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.CAMERA" />
<uses-permission android:name="android.permission.RECORD_AUDIO" />
<uses-permission android:name="android.permission.MODIFY_AUDIO_SETTINGS" />
<uses-feature android:name="android.hardware.camera" android:required="false" />
```

The camera and microphone need no Java code. When the page calls `getUserMedia`, Capacitor's WebChromeClient asks Android for
the matching permission, and Android shows its normal dialog. That only works for permissions declared in the manifest.
`MODIFY_AUDIO_SETTINGS` is what the WebView needs for microphone capture. No `network_security_config.xml` is needed with an
https tunnel.

2.4 After the first run, check `frontend/android/variables.gradle` against step 1.4.

## 3. The build-and-install script

```bash
cd /c/Projects/AiFitnessTracker && backend/.venv/Scripts/python scripts/build_and_serve_apk.py --url https://<words>.trycloudflare.com
```

What it does:

1. Takes the URL from `--url`, else `TUNNEL_URL` (environment or `backend/.env`), else asks. It refuses a URL with a token in it.
2. Writes `frontend/capacitor.config.json`, builds `dist` if it is missing, runs `npx cap add android` the first time, patches the
   manifest, runs `npx cap sync android` and `gradlew.bat assembleDebug`.
3. Copies the APK to `frontend/android/app/build/share/AI-Fitness-Tracker.apk`, serves only that folder on `0.0.0.0:8080`, and
   prints a QR code for `http://<laptop LAN IP>:8080/AI-Fitness-Tracker.apk`.

Options: `--serve-only` (no rebuild), `--adb` (install over USB instead of the QR code), `--ip` (if it picks the wrong network
adapter, e.g. DroidCam, VPN or WSL; take the Wi-Fi adapter's IPv4 from `ipconfig`), `--port`.

The first build downloads Gradle and its libraries and takes several minutes. Do it **today**, not just before the demo.

Windows Firewall: the first time, Windows asks whether Python may accept connections. Allow it on **Private** networks, and make
sure the Wi-Fi network profile is Private. Or, once, in an administrator PowerShell:

```powershell
New-NetFirewallRule -DisplayName "APK share 8080" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow -Profile Private
```

Copy the `https://<words>.trycloudflare.com` it prints and open it once in the laptop browser to check it works.

**Terminal 3, APK:**

```bash
cd /c/Projects/AiFitnessTracker && backend/.venv/Scripts/python scripts/build_and_serve_apk.py --url https://<words>.trycloudflare.com
```

**Phone (same Wi-Fi):**

1. Open the camera and scan the QR code. Chrome downloads the APK; keep it if Chrome warns about the file type.
2. Open the download and install. Play Protect may say the app is unknown: choose **Install anyway**.
3. Open **AI Fitness Tracker** and enter the access token once.
4. Tap Start camera and allow the camera. Allow the microphone on the first voice use.
5. Ctrl+C in terminal 3.

Alternative to steps 1-2: with the USB cable connected and debugging allowed, `... build_and_serve_apk.py --serve-only --adb`.

**Mirror the phone (USB):**

```bash
scrcpy --stay-awake --show-touches --no-audio --max-size 1600 --video-bit-rate 8M --max-fps 60 --window-title "AI Fitness Tracker - Live Demo"
```

- `--stay-awake` keeps the phone awake while plugged in. `--show-touches` lets the audience see your taps. `--max-size 1600` and
  8 Mbit/s are smooth over USB with low delay.
- `--no-audio` keeps sound on the phone's speaker, so voice prompts and the fall alarm are heard in the room. Without it scrcpy
  forwards the sound to the laptop, and on Android 13 and later mutes the phone while it does.
- Press `F11` (or `Alt+F`) for full screen on the projector.
- If you get "adb server version doesn't match": scrcpy brought its own `adb`. Make it use the SDK one with
  `export ADB="$LOCALAPPDATA/Android/Sdk/platform-tools/adb.exe"` before running scrcpy.
- Wireless, if the cable is in the way: once over USB `adb tcpip 5555`, unplug, `adb connect <phone IP>:5555`, then scrcpy.
  USB is more reliable for a demo.

### If something goes wrong

| Symptom | Fix |
|---|---|
| App shows "Webpage not available" | The tunnel is down or got a new address: restart it, then re-run the script with the new URL and reinstall |
| Camera stays black, no permission dialog | URL is not https, or the permission was denied: Settings > Apps > AI Fitness Tracker > Permissions |
| Token screen every time | Enter it again; the browser fallback works the same way |
| "Remote sessions are switched off" | `REMOTE_SESSIONS=1` missing in `backend/.env` |
| QR link does not load on the phone | Different Wi-Fi, firewall (section 3), or wrong adapter: `--ip` |
| "App not installed" | An old build signed differently: uninstall the app first, then install again |
| Anything else during the demo | Open the tunnel URL in Chrome on the phone: the same app |

## 5. Known limits of the wrapper

- The phone must reach the tunnel. The APK has no offline mode, because the app and the analysis come from the laptop.
- As in the browser, the camera stops when the screen is off or the app is in the background, so there is no background fall
  monitoring. That needs the native camera plugin from `docs/mobile-performance-roadmap.md`, Phase C.
- The full-screen button may not cover the system bars inside the WebView. The HUD's in-page full-screen fallback still works.
- The debug APK is signed with a debug key: fine for a demo, not for distribution.
